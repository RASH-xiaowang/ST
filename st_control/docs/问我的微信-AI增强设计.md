# 「问我的微信」AI 增强设计（Agent 化多轮 RAG）

## 目标

把「问我的微信」从一次性「规划 → 检索 → 回答」升级为 Agent 化问答：
能回答统计类问题（多少条 / 谁最活跃 / 趋势）、首轮搜不到会自动补检、
支持追问消解，并让检索过程对用户透明。

## 现状（改造前）

1. LLM 只做一次检索规划（关键词 / 目标会话 / 时间 / 数据源）；
2. 本地只按关键词搜消息，最多取 24~60 条引用；
3. 一次性回答，不评估证据是否足够，也不支持统计计算；
4. 无对话记忆，追问（「那去年呢？」）会当作全新问题；
5. 检索失败直接说「没有数据」，不会换词再搜。

## 改造后的流程

```
问题 + 最近 6 轮对话历史
        │
        ▼
① 检索规划（LLM，失败回退启发式）
   plan: keywords / target / time / data_sources / aggregation
        │
        ▼
② Agent 循环（最多 3 轮）
   检索消息/记录 ──→ 合并去重证据
   统计工具      ──→ 消息计数 / 会话排行 / 月度趋势 / 转账红包计数
        │
        ▼
③ LLM 自评（reflect）
   证据足够？→ 标出相关引用序号，结束
   不足？    → 输出 refinement（换词 / 扩时间 / 换源 / 补聚合）→ 回到 ②
        │
        ▼
④ 生成回答（LLM）
   依据全部证据 + 统计表，带【序号】引用
```

## 新增能力

### 1. 统计 / 聚合工具（本地 SQL 聚合）

| 类型 | 说明 | 示例问题 |
| --- | --- | --- |
| `count_messages` | 按会话/时间/关键词统计文本消息条数，无目标时给 Top 会话分布 | 「我和张三上周聊了多少条消息」 |
| `top_sessions` | 消息量排行（可只看群聊） | 「我上个月和谁聊得最多」「哪些群最活跃」 |
| `message_trend` | 按月消息量趋势 | 「今年的消息趋势」 |
| `count_transfers` | 转账笔数（按会话/时间） | 「我去年转了几笔账」 |
| `count_redpackets` | 红包个数（按会话/时间） | 「我最近收了多少红包」 |

统计结果以表格形式返回前端展示，并作为证据参与 AI 回答。
消息统计基于 `wechat_search.db` 索引（需先构建消息索引）；转账/红包统计基于 `general.db`。

### 2. 多轮自评补检（Reflect）

每轮检索后让 LLM 判断证据是否足够回答：

- 足够 → 标出相关引用序号（`relevant_indices`），过滤噪音后生成回答；
- 不足 → 输出 refinement 计划（换关键词 / 扩时间 / 换数据源 / 补统计），继续下一轮；
- 最多 3 轮，控制延迟与成本。

### 3. 对话历史 / 追问

前端把最近 6 轮 Q&A 传给后端，规划与回答提示词中带上历史，
支持「那去年呢？」「具体是谁？」这类追问的上下文消解。

### 4. 过程透明

后端返回 `steps`（每轮检索/统计记录）与 `stats`（统计表），
前端在回答下方展示，用户可以看清 AI 是怎么找到答案的。

## 主要改动

- `src-tauri/src/wechat/ask.rs`：新增 `AggregationSpec` / `StatsTable` / `AskHistoryItem`，
  启发式统计识别、聚合执行、reflect 自评循环、历史上下文、steps 输出；
- `src-tauri/src/wechat/general_records.rs`：新增 `stats_transfers` / `stats_redpackets`；
- `src/lib/wechat/services/ipc.ts`：`askWechat` 增加 history 参数；
- `src/lib/wechat/components/AskPanel.svelte`：传历史、展示统计表与检索过程、更新示例问题。

## 无模型时的降级行为

未配置大模型提供方时保持原有能力：启发式规划 + 单轮检索，
统计类问题仍可返回统计表与证据（无 AI 文字回答）。

## 后续可迭代方向

- 检索结果用重排序模型（rerank）排序后再进自评；
- 统计工具扩展：金额汇总（需解析转账金额字段）、关键词词频、消息类型分布；
- 流式输出回答，减少等待感；
- 常用问题结果缓存。
